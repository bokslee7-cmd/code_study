# TASK-055. ProjectDetail 페이지

## 상태
완료

## 날짜

## 작업 요약
카드를 눌렀을 때 도착하는 **프로젝트 상세 페이지**를 만들었다. 책의 표지 안쪽 "책 소개 면"에 해당하며, 아직 본문(태스크)은 없어서 "준비 중" 쪽지를 붙여 두었다.

| 영역 | 내용 |
|------|------|
| 상단 | `대시보드로 돌아가기` 링크 (로딩/오류 상태에서도 항상 표시) |
| 정보 | 제목(h1), 설명(없으면 `설명이 없습니다.`), `생성일: 2026년 11월 1일`, 진행률(`0/0 태스크 완료`, 퍼센트, 진행 막대) |
| 태스크 타임라인 | h2 `태스크 타임라인` + `태스크 타임라인은 준비 중입니다.` placeholder (Task 모델/API가 생기면 교체) |

| 상태 | 화면 |
|------|------|
| 로딩 | `프로젝트를 불러오는 중입니다...` |
| 403 | `이 프로젝트에 접근할 권한이 없습니다.` (재시도 버튼 없음) |
| 404 | `프로젝트를 찾을 수 없습니다. 삭제되었거나 주소가 잘못되었을 수 있습니다.` (재시도 버튼 없음) |
| 그 밖의 오류 | 서버 한국어 메시지 + **다시 시도** 버튼 (서버 메시지가 없으면 일반 안내) |

403/404는 서버가 영어 메시지를 줄 수 있고 다시 시도해도 결과가 같으므로, 화면에서 정한 한국어 문구를 쓰고 재시도 버튼을 숨겼다. 쿼리 키는 `["projects", projectId]`다.

**라우팅**: `/projects/:projectId` 보호 라우트에 연결했다. 카드 클릭(`/projects/{id}`)으로 이동한다.

## 기술 결정
- **403/404는 재시도하지 않음**: `queryClient.shouldRetry`가 4xx를 재시도하지 않는 것과 같은 이유로, 화면에도 "다시 시도" 버튼을 두지 않았다. 대신 돌아가기 링크가 항상 있다.
- **상태별 `alert` 하나**: 오류 종류와 무관하게 `role="alert"` 영역 하나에 메시지를 두어 스크린리더가 즉시 읽는다.
- **placeholder는 최소**: 태스크 타임라인은 제목과 안내 문구만 둔다. 실제 타임라인은 Task API 이후 별도 태스크에서 구현한다.

## 비고
- **실제 백엔드와 통합 시 확인할 점**: 403(타인 프로젝트)과 404(없음/삭제됨)가 계약대로 구분되어 오는지 브라우저 테스트(T057~)에서 확인이 필요하다. 서버가 403 대신 404로 응답해도 화면은 문제없이 동작한다(안내 문구만 달라짐).
- Git 저장소가 아니라 커밋은 없다.
