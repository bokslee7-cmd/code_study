## 작업 요약
`backend/src/services/ai/prompts.py`에 학습 문서 생성용 프롬프트를 만들었다. 입출력이 없는 순수 함수와 상수로만 구성된다.

- `SYSTEM_INSTRUCTION`: 프로그래밍 지식이 전혀 없는 사람을 가르치는 선생님, 한국어, JSON만 출력.
- `CHAPTER_SCHEMA`: 7챕터 JSON 스키마(필드명은 plan_specify.md 기준). T093이 응답 검증에 그대로 재사용한다.
- `STANDARD_DEFINITIONS`: 변수·함수·반복문 등 8개 개념의 표준 정의(requirements-addendum CHK026).
- `build_document_prompt(files, language=, complexity_level=None, problems=())`: 프롬프트 한 편을 만든다. 챕터별 요구사항(FR-027~034)과 공통 규칙(FR-035~037)을 담고, 코드는 줄 번호를 붙여 넣는다. `problems`에 이전 시도의 문제점을 주면 재시도용 프롬프트가 된다(CHK006).

## 기술 결정
- **JSON은 프롬프트로만 강제한다.** 고정 SDK(0.3.0)에는 JSON 모드가 없다(TASK-091 참고). "JSON 객체 하나만, 마크다운 코드 블록 금지"를 시스템 지시문과 프롬프트 끝에 반복했고, 파싱과 검증은 T093이 맡는다.
- **코드는 `=== FILE: 경로 (언어) ===`와 `=== END FILE ===`로 감싸고 모든 줄 앞에 `   1| ` 형식의 번호를 붙인다.** 번호가 붙은 줄은 구분선과 구별되므로 코드 안에 같은 문자열이 있어도 구분선을 위조할 수 없고, 챕터 4의 `line_number`가 정확해진다. 줄바꿈은 `\n`, `\r\n`, `\r`만 줄로 센다. 코드 안의 지시문을 따르지 않도록 하는 문구도 넣었다.
- **필드명은 plan_specify.md를 따랐다.** data-model.md는 챕터 4~7의 세부 필드를 `[...]`로 비워 뒀다. 챕터 5의 `data_state`는 문자열(예: `a=2, b=3`)로 정했다. 문서에 명시가 없어 내가 정한 값이다.
- **`chapter4.file_path`를 추가했다.** 여러 파일 업로드(폴더)에서는 줄 번호만으로 어느 파일인지 알 수 없어서 넣은 항목이다. plan_specify.md에는 없으므로 한 파일이면 빈 문자열이다. 프런트(T100 CodePanel)가 쓰지 않으면 무시하면 된다.
- **설명은 한국어, 코드·식별자는 원문**으로 쓰게 했다. spec.md 가정 6번("코드 설명은 영어 가능")보다 사용자 언어를 우선했다.
- `prompts.py`의 챕터·규칙 상수 3개에만 `# fmt: off`를 썼다. black은 문자 수 기준으로 줄 바꿈한 문자열을 한 줄로 합치는데, ruff는 한글을 넓은 글자로 세어 E501을 내서 두 도구가 충돌했다.

## 비고
- 온도(temperature)와 `max_output_tokens`는 이 파일에 넣지 않았다. T093에서 정한다. addendum은 재시도 시 0.7→0.8을 제안하고, FR-039(같은 코드는 같은 구조)와는 긴장이 있다. `max_output_tokens`는 작게 주면 응답이 비므로 지정하지 않는 것이 안전하다(TASK-091).
- 챕터 4는 "모든 코드 줄"을 설명시키므로 500줄 코드에서는 출력이 매우 길어진다. 3분 제한(FR-025)과 토큰 한도에 걸릴 수 있어 T093에서 대용량 코드의 분할 생성이 필요한지 판단해야 한다. 실측은 9줄 코드뿐이다.
- 이 프롬프트에는 CHK005의 "챕터마다 비유 1개 이상"(키워드 검증)과 "2개 이상의 부분 응답 수용" 같은 검증·폴백 로직은 없다. T093의 몫이다.
