## 작업 요약
퇴장 창구를 열었다. 손님이 나갈 때 지갑 속 정기권(리프레시 토큰 쿠키)을 창구에 내밀면 직원이 장부에서 그 정기권을 "사용 중지" 처리하고(`UserService.logout`), 손님의 주머니에서 정기권도 빼 준다(쿠키 삭제). 정기권이 없거나 이미 중지된 것이거나 처음 보는 것이어도 "알겠습니다, 안녕히 가세요"(204)로 똑같이 응대한다. 몇 번 눌러도 결과가 같다(멱등).

| 상황 | 결과 |
|------|------|
| 유효한 쿠키 | 서비스가 토큰 폐기, 쿠키 삭제 헤더, 204 |
| 쿠키 없음/빈 값 | 서비스 호출 없이 쿠키 삭제 헤더, 204 |
| 알 수 없거나 이미 폐기된 토큰 | 서비스가 조용히 넘어감, 204 |
| `Authorization` 헤더 | 필요 없음 |

## 기술 결정
- **인증 없이 동작**: 액세스 토큰이 이미 만료된 상태에서도 로그아웃할 수 있어야 하므로 `CurrentUser`를 쓰지 않고 쿠키만 읽는다. 쿠키의 토큰 자체가 폐기 대상의 증거다.
- **삭제 쿠키의 속성을 설정 때와 동일하게**: 브라우저는 이름과 `Path`가 다르면 다른 쿠키로 보므로 같은 `Path=/api/v1/auth`와 `Secure` 설정으로 `Max-Age=0`을 내려야 실제로 지워진다(테스트로 확인).
- **쿠키 유무와 관계없이 항상 204**: 쿠키가 없다고 오류를 내면 "로그인 상태인지"를 외부에서 떠볼 단서가 되고, 클라이언트도 재시도 처리가 번거로워진다.
- **빈 쿠키 값은 쿠키 없음과 같게 취급**: 불필요한 DB 조회를 하지 않는다.

## 비고
- 이미 발급된 액세스 토큰은 서버에 저장하지 않으므로 로그아웃해도 만료(기본 15분)까지 유효하다. 이는 T026 설계(`verify_access_token`은 무상태)에서 이미 정해진 한계다.
