# TASK-056. Dashboard 프로젝트 생성 플로우 연결

## 상태
완료

## 날짜

## 작업 요약
T051~T055에서 따로 만든 부품(카드, 입력 팝업, 서비스, 목록 쿼리)을 **한 줄로 이어서** 실제로 프로젝트를 만들 수 있게 했다. 식당에서 주문서 양식(팝업)·주방(서버)·홀 메뉴판(목록)이 따로 준비돼 있다가, 주문 → 조리 → 테이블 서빙이 한 흐름으로 연결된 것이다.

흐름:
1. 대시보드 상단의 **새 프로젝트** 버튼, 또는 빈 상태의 **첫 프로젝트 만들기** 버튼을 누르면 팝업이 열린다.
2. 제목(과 설명)을 입력하고 **만들기**를 누른다 → `createProject` 호출.
3. 성공하면 `["projects"]` 쿼리를 무효화(invalidate)해 목록을 다시 불러온다. 목록 갱신이 끝날 때까지 팝업은 "만드는 중..." 상태로 남아 있다가 닫히므로, 닫힌 뒤에는 새 프로젝트가 이미 보인다.
4. 서버가 제목 오류(400)를 주면 팝업을 유지하고 제목 입력란 아래에 메시지를 보여준다. 취소하면 닫히고 포커스가 팝업을 연 버튼으로 돌아간다.

| 시나리오 | 확인 내용 |
|----------|-----------|
| 새 프로젝트 버튼 | 대화상자가 열림 |
| 빈 상태 버튼 | 대화상자가 열림 (프로젝트가 있으면 이 버튼은 없음) |
| 만들기 성공 | `createProject`가 `{title, description: null}`로 호출됨, 목록 2회 조회, 새 카드 표시, 대화상자 닫힘 |
| 서버 제목 오류 | 대화상자 유지 + 제목 오류 문구 |
| 취소 | 대화상자 닫힘, 포커스가 "새 프로젝트" 버튼으로 복귀, API 호출 없음 |

## 기술 결정
- **성공 후 `invalidateQueries`를 반환(await)**: 목록 재조회가 끝나야 팝업이 닫히게 해서 "닫혔는데 목록에 아직 없음" 깜빡임을 막는다.
- **생성 후 상세 페이지로 이동하지 않음**: 요구사항이 "성공 시 닫고 목록 갱신"이므로 그대로 따랐다.
- **버튼 두 개가 같은 `isCreating` 상태를 공유**: 팝업을 여는 경로가 둘이어도 팝업은 하나만 뜬다.

## 비고
- **실제 백엔드와 통합 시 확인할 점**: 제목 오류 응답의 `details.field`가 정확히 `"title"`이어야 필드 오류로 표시된다. 다른 형태면 팝업 안 일반 알림으로 보인다(기능은 동작).
- 빈 상태의 "첫 프로젝트 만들기"로 열었다면, 생성 후 그 버튼이 사라지므로 포커스는 문서 맨 위(`body`)로 간다. 허용 가능한 한계로 보고 별도 처리하지 않았다.
- 브라우저 수동 테스트(T057~T060)와 수정/삭제 UI는 이번 범위가 아니다. 개발 서버와 브라우저 자동화는 사용하지 않았다.
