# TASK-038A. 401 응답 시 토큰 갱신 후 요청 재시도

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
출입증(액세스 토큰)이 만료된 채로 서류를 제출했을 때, 접수 창구가 "출입증이 만료됐네요" 하고 돌려보내는 대신 **직원이 알아서 새 출입증을 받아 와서 같은 서류를 다시 접수**해 주는 기능을 만들었다. 사용자는 중간에 끊기지 않는다.

T038의 타이머 갱신은 "만료 1분 전"에 미리 새 토큰을 받는 방식이라, 컴퓨터가 절전 모드였거나 탭이 오래 백그라운드에 있어 타이머가 못 돌았을 때는 그대로 만료된다. 그 빈틈을 이 태스크가 메운다.

| 상황 | 동작 |
|------|------|
| 보호된 요청이 401 | 토큰 갱신 → 새 토큰으로 같은 요청을 **한 번** 다시 보냄 |
| 요청 3개가 동시에 401 | 갱신 요청은 **1번만** 보내고 3개 모두 재시도 (리프레시 토큰이 1회용이라) |
| 이미 다른 요청이 토큰을 갱신해 둠 | 다시 갱신하지 않고 현재 토큰으로 재시도 |
| 재시도도 401 | 반복하지 않고 401 오류로 종료 |
| 갱신 자체가 실패 | 세션을 비우고(→ 로그인 화면) 원래의 401 오류를 반환 |
| `/auth/*` 요청(로그인·가입·갱신·로그아웃·me)의 401 | 갱신하지 않음. 그 401은 "토큰 만료"가 아니라 결과 자체 |
| 토큰 없이 보낸 요청(비로그인)의 401 | 갱신하지 않음 |

## 기술 결정
- **갱신 함수를 주입 방식으로 등록**: `api-client`가 스토어와 `auth-service`를 직접 import하면 순환 의존이 된다(`auth-service`가 `api-client`를 쓴다). 토큰 공급자(`setAuthTokenProvider`)와 같은 방식으로 `session-refresh`가 등록한다. `useAuth`가 이 모듈을 import하므로 앱이 시작되면 자동으로 등록된다.
- **동시 갱신은 하나로 합침**: 리프레시 토큰은 갱신할 때마다 새 것으로 교체되고 옛 것은 폐기된다. 요청 3개가 각자 갱신하면 2개는 이미 폐기된 토큰으로 가서 401이 나고 세션이 깨진다.
- **"이미 갱신됐는지" 확인**: 낡은 토큰으로 나간 요청의 401이 갱신 완료 뒤에 도착할 수 있다. 요청에 실린 토큰과 현재 토큰을 비교해 다르면 갱신 없이 재시도한다.
- **`/auth/*` 제외**: 로그인 실패(401)는 "비밀번호가 틀렸다"는 결과이므로 갱신을 시도하면 오히려 잘못된 동작이 된다. `/auth/refresh` 자신이 401일 때 무한히 갱신하는 일도 막는다.
- **갱신 중 로그아웃된 경우**: 갱신 응답이 왔을 때 스토어에 토큰이 없으면(그사이 로그아웃) 세션을 되살리지 않고 실패 처리한다. T038에서 정한 규칙을 그대로 유지했다.
