## 작업 요약
회원증을 이미 가진 사람이 도서관 입구에서 내미는 "출입 카드 확인대"를 화면에 만들었다. 이메일과 비밀번호 두 칸, "로그인" 버튼이 전부다. 회원가입 양식(T032)과 같은 부품(`FormField`, `useSubmitState`, `auth-validation`)을 쓰고, 다른 점은 비밀번호 규칙이다.

| 상황 | 화면 반응 |
|------|-----------|
| 이메일/비밀번호가 비어 있음 | 칸별 안내, 제출하지 않음 |
| 이메일 형식 오류 | "올바른 이메일 형식이 아닙니다." |
| 비밀번호가 짧음(예: 5자) | 막지 않고 그대로 서버에 보냄 |
| 검증 통과 | 이메일 공백을 지운 `{email, password}`로 `onSubmit` 호출 |
| 제출 중 | 버튼 비활성화 + "로그인 중..." |
| 로그인 실패(401 등) | 서버 메시지를 `role="alert"`로 표시. 다시 제출하면 이전 오류는 사라짐 |

## 기술 결정
- **로그인에서는 비밀번호 최소 길이를 검사하지 않음**: 요청 지침은 "이메일 형식, 비밀번호 최소 길이" 검증이었지만, 로그인 쪽에서 길이를 막으면 가입 규칙이 나중에 바뀔 때 기존 사용자가 로그인 자체를 못 하게 된다. 입력 여부만 확인하고 판단은 서버(401)에 맡겼다. 길이 검증은 회원가입(T032)에만 둔다. 이 판단을 테스트로 고정해 두었다("5자 비밀번호도 서버에 전달").
- **에러 문구는 한 군데(`role="alert"`)에만**: 로그인 실패 사유를 이메일/비밀번호 중 어느 쪽이라고 알려주지 않는다. 서버가 주는 "이메일 또는 비밀번호가 올바르지 않습니다." 같은 문구를 그대로 보여준다(계정 존재 여부 노출 방지).
- **`autoComplete`**: 이메일은 `email`, 비밀번호는 `current-password`로 지정해 브라우저/비밀번호 관리자가 채우기 쉽게 했다.
